# Пояснение к диаграмме C4

## Роль IAM

IAM (Keycloak) — единый центр управления идентификацией и доступом в контуре BionicPRO. Он отвечает за выпуск и валидацию JWT‑токенов, управление сессиями и централизованный отзыв прав.

## Аутентификация

- **Пользователи** (пилот, оператор, покупатель) — проходят аутентификацию в IAM и получают JWT для доступа к функциональности системы.  
- **cli tool** — использует поток `client_credentials` для автоматизированных фоновых операций.  
- **Внешние IdP** (филиалы RU/DE) — интегрированы с IAM для федерации удостоверений: вход по корпоративным учётным записям без дублирования аккаунтов.

## Интроспекция токенов

Интроспекция (`/introspect`) применяется в сервисах, где требуется гарантия актуальности прав в момент запроса — локальная проверка подписи JWT для этого недостаточна:

- **API (Spring Boot)** — выполняет интроспекцию для каждого защищённого запроса. Это исключает доступ по токенам, которые были отозваны администратором после выдачи.  
- **CRM (Битрикс24)** — использует интроспекцию при обращении к данным заказов и профилям клиентов, чтобы строго контролировать уровень доступа в реальном времени.  
- **Интернет‑магазин** — проверяет токены при операциях с заказами и персональными данными, гарантируя, что действия выполняются только при подтверждённой и неотозванной сессии.

## Преобразование и переподписывание JWT

При интеграции с внешними IdP IAM не просто передаёт токены, а трансформирует их под внутренние стандарты безопасности:

- **Преобразование токенов**: IAM принимает токен от внешнего IdP, валидирует его и формирует собственный JWT, содержащий только утверждённые (claims) и в нужном формате.  
- **Переподписывание**: все токены, используемые внутри BionicPRO, подписаны ключами IAM. Это снимает с сервисов необходимость доверять множеству внешних провайдеров и унифицирует проверку прав.

## Почему IAM не используется для телеметрии

Поток технической телеметрии от «Программы в чипе протеза» отделён от пользовательского контура авторизации и защищён на транспортном уровне:

- **Аутентификация по сертификатам (mTLS)** — устройства могут идентифицироваться с помощью уникальных X.509‑сертификатов, выданных внутренним PKI. Это машиночитаемая идентификация, не требующая JWT и обращения к IAM.
